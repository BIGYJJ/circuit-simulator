# FLUXLAB 可信电路仿真平台现代化需求

## Purpose

把当前由固定实验公式和演示型工程面板组成的应用，重建为一个从初学者到高级工程师都使用同一份项目、同一条仿真链和同一份证据的本地优先电路工作台。

用户价值不是“增加更多实验入口”，而是让任何一个读数都能追溯到电路拓扑、器件参数、模型、分析方法、引擎版本和具体运行快照。

## Current Behavior

- 分压器、RC、LED 使用三个不同的专用求解函数；它们只识别固定模板或直接忽略部分拓扑。
- `engineering-core.ts` 和 `engineering-ops.ts` 提供互不相连的演示公式、静态目录和硬编码门禁，不消费当前用户项目。
- 五个路由代表五个孤立页面，没有连续学习项目、统一分析快照或真实版本历史。
- 源码归档含明文凭据；生产依赖审计存在高危项；开发模板、遥测和未使用组件仍在交付物中。
- 在隔离副本中，31 个现有单元测试、类型检查和生产构建可以通过，但这些检查不能证明拓扑正确、工程门禁可信或真实用户路径可用。

## Desired Behavior

- 一个版本化项目可以从基础课程一路进入自由编辑、DC、瞬态、AC、扫描、断言和设计评审。
- 初学者界面是同一项目工作台上的渐进式引导，不是另一个简化求解器。
- 所有受支持分析由浏览器内 Web Worker 中固定版本的 ngspice WebAssembly 执行。
- 所有页面、仪器、ERC、断言、角点和导出只消费可追溯 `RunRecord`；数值只来自其中成功状态的 `SimulationSnapshot`。
- 不受支持的语法、拓扑、模型或资源规模必须明确失败，不能静默忽略或伪造通过。
- 首次成功加载并缓存后，断网仍可打开项目并完成仿真；项目和模型默认不离开设备。

## Scope

### In Scope

- 现有 React、TypeScript、Vite 单应用内的现代化重构。
- 统一项目文档、原理图编辑器、网表编译器、结构/ERC 检查和 ngspice Worker 适配器。
- DC 工作点、DC 扫描、瞬态和 AC 分析。
- R、C、L、独立 V/I 源、开关、二极管、BJT、MOSFET、GND 和受控的 `.model`/`.subckt` 引用。
- 电压/电流探针、示波器、Bode 图、运行对比、断言、角点和可追溯导出。
- 基础、进阶、工程三级渐进式学习体验。
- v1 项目到 v2 项目的显式迁移，以及旧结果作废和重新计算。
- 凭据、遥测、依赖、模板残留和发布流程整顿。

### Out of Scope

- 自研完整 SPICE 数值内核或器件模型库。
- 数字事件仿真、混合信号协同仿真、PCB 布局布线、SI/PI、EMI、热分析。
- 云同步、账号、多用户协作、在线模型市场和远程仿真队列。
- 硬件安全认证、生产签核或替代实物测量。
- 第一阶段的 KiCad/Altium 双向工程兼容。
- 在手机上完成大型原理图编辑；360 px 保证课程、参数、运行和结果查看，768 px 支持轻量编辑，1024 px 以上支持完整工程工作台。

## Critical Requirements

| ID | Given/current state | User action | Observable result | Acceptance evidence |
|---|---|---|---|---|
| R1 | 当前多个求解器互不相连 | 用户编辑任意受支持拓扑并运行分析 | 结果由同一编译和 ngspice Worker 链产生 | 断线、短路、并联负载、多支路夹具及浏览器实测 |
| R2 | 初学和高级页面使用不同状态 | 用户从课程模板进入完整工作台 | 项目 ID、拓扑、参数、运行历史不变 | 端到端课程到工程视图测试 |
| R3 | 结果缺少来源 | 用户查看任意波形或读数 | 可见项目修订、分析配置、模型哈希、引擎版本和运行状态 | `RunRecord`/`SimulationSnapshot` 契约测试及 UI 检查 |
| R4 | ERC 和门禁可硬编码通过 | 用户修改项目后运行验证 | ERC、断言、角点和门禁引用真实项目修订及快照；旧结果过期 | 变更前后快照与门禁回归测试 |
| R5 | SPICE 文本可静默忽略语句 | 用户导入网表或模型 | 支持项被解析；每个不支持或危险项带行号拒绝 | 导入诊断夹具，不允许静默丢行 |
| R6 | 应用声称本地优先但含遥测/代理 | 用户运行和保存项目 | 电路、模型、波形不产生外发请求 | 断网验收和浏览器网络记录 |
| R7 | 归档包含凭据 | 维护者生成发布包 | 包内无凭据、私有配置或生成器状态 | 密钥扫描、归档清单和旧凭据失效记录 |
| R8 | 坏 JSON 可导致页面崩溃 | 用户打开旧项目或导入坏文件 | 显示可定位诊断并保持工作台可用 | 破损、缺字段、超限、v1 迁移测试 |
| R9 | 当前 31 个测试只固定演示公式 | 开发者提交每个纵向切片 | 先证明改变的用户行为，再验证受影响回归和风险 | CI 证据及真实浏览器验收记录 |
| R10 | 当前依赖和页面大多是模板残留 | 用户首次加载应用 | 主包、依赖和攻击面收缩，高级能力按需加载 | 构建体积对比、依赖审计和路由 smoke |

新手任务成功率、工程用户任务、概念学习增益、viewport、性能、依赖和包体的唯一量化口径见 `02-design.md` 第 16 节；这些都是未来发布门禁，当前审计尚未验证。

## Compatibility and Existing Data

- `CircuitDocument.version === 1` 的电路事实尽可能迁移；未知或歧义字段必须生成诊断。
- v1 的仿真结果、完成标记、工程门禁和硬编码分析记录不具有可信来源，不迁移为已验证证据。
- v1 的 `x/y` 坐标迁移到 v2 `layout`，元件和导线 ID 在不冲突时保留。
- 现有分压和 RC 数值作为新引擎的黄金基线；LED 固定压降结果仅作为历史教学说明，不作为 ngspice 器件结果的兼容承诺。
- v1 LED 的单值 `learning-progress` 一律不迁移为完成证据；v2 LED 教学模板的默认参数必须位于目标电流窗口外，并要求真实调参和成功 run 才能完成。
- 导入后保存使用 v2；不提供 v2 到 v1 的反向降级。

## Failure Behavior and Safety Baseline

- 编译、模型加载、ngspice 运行、超时、取消和结果解析均返回结构化失败状态，绝不复用旧成功快照。
- 参数变化立即令相关快照标记为 `stale`；UI 不得继续显示“通过”或“可交付”。
- Worker 超过资源限制或用户取消时直接终止并重建，避免主线程和后续运行被污染。
- 导入只允许明确支持的 SPICE 数据语句；拒绝 `.control`、`.shell`、任意文件访问和网络引用。
- 所有安全、电流、功耗和额定诊断都标明模型来源与“非硬件认证”边界。

## Constraints and Approved Assumptions

- 已批准方案 A：单一工作台、ngspice WebAssembly、Web Worker、纯浏览器离线运行。
- 保留 React 19、TypeScript、Vite 和当前深色工作台视觉资产中可复用的部分。
- 不拆 monorepo，不引入服务端数据库或第二套权威求解器。
- ngspice 版本、构建来源、许可证和 SHA-256 必须固定在仓库内；禁止运行时从 CDN 漂移加载。
- 仿真必须在 Worker 内执行；React 页面不得直接计算最终工程结果。
- 新增依赖须能删除明显更多自有代码或满足明确的离线/安全要求。
